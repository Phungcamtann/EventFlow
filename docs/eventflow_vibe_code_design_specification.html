Kiến Trúc Tổng Thể Hệ Thống (Three-Tier Monolith Architecture)

Theo Mục V (Hồ sơ Tuần 3), hệ thống sử dụng kiến trúc 3 lớp chạy trên một ứng dụng PHP nguyên khối (Monolith) kết hợp MySQL (InnoDB). Trình duyệt không kết nối trực tiếp CSDL mà giao tiếp hoàn toàn qua Backend PHP.

Lớp 1: Presentation Layer Client-side

Giao Diện Website (Responsive)

  • Công nghệ: HTML5, CSS3, Bootstrap 5, Vanilla JavaScript.
  • Trách nhiệm: Hiển thị giao diện theo 4 vai trò (System Admin, Club Manager, Club Member, Event Participant).
  • Nhận dữ liệu từ biểu mẫu (Form) hoặc gửi yêu cầu bất đồng bộ (Fetch/AJAX JSON) cho các thao tác cần phản hồi nhanh như tra cứu & check-in.
  • Tương thích máy tính (Windows 10/11, macOS 14+) và điện thoại (Android 10+) theo NFR07.
Giao thức: HTTP/HTTPS (Form POST/GET & JSON)
Lớp 2: Application Layer Server-side

Xử Lý Nghiệp Vụ (Apache & PHP)

  • Xác thực & Phiên: PHP Session, băm mật khẩu bằng password_hash() và kiểm tra bằng password_verify().
  • Bảo mật: Kiểm tra RBAC trên mọi request, kiểm tra CSRF Token cho request thay đổi dữ liệu, escape output bằng htmlspecialchars() chống XSS.
  • 5 Phân hệ nghiệp vụ:
    1. Tài khoản & Phân quyền hệ thống
    2. Hồ sơ CLB & Thành viên
    3. Quản lý Sự kiện
    4. Đăng ký sự kiện (Transaction + Row Locking)
    5. Điểm danh (Check-in) & Thống kê cơ bản
Kết nối CSDL: PDO (Prepared Statements)
Lớp 3: Data Layer Database

Cơ Sở Dữ Liệu (MySQL InnoDB)

  • Hệ quản trị: MySQL sử dụng Storage Engine InnoDB.
  • 7 Bảng thực thể: Role, Account, Club, Club_Member, Event, Event_Registration, Attendance.
  • Toàn vẹn dữ liệu (NFR01): Ràng buộc khóa ngoại (FK), chỉ mục duy nhất UNIQUE(EventID, AccountID), UNIQUE(RegID).
  • Xử lý đồng thời: Hỗ trợ ACID Transaction và khóa bản ghi SELECT ... FOR UPDATE.
  • Công cụ quản trị: phpMyAdmin (chỉ dành cho nhóm phát triển/vận hành).
Engine: InnoDB · Charset: utf8mb4_unicode_ci

-- ============================================================================
-- EVENTFLOW DATABASE SCHEMA & SEED DATA (MYSQL INNODB)
-- Phạm vi: MVP 01 CLB Tiếng Anh Sinh Viên (7 Bảng Chuẩn Hóa 3NF)
-- ============================================================================

CREATE DATABASE IF NOT EXISTS eventflow_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE eventflow_db;

-- 1. Bảng Role (Vai trò hệ thống)
CREATE TABLE IF NOT EXISTS Role (
    RoleID INT AUTO_INCREMENT PRIMARY KEY,
    RoleName VARCHAR(50) NOT NULL UNIQUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 2. Bảng Account (Tài khoản người dùng)
CREATE TABLE IF NOT EXISTS Account (
    AccountID INT AUTO_INCREMENT PRIMARY KEY,
    Email VARCHAR(100) NOT NULL UNIQUE,
    PasswordHash VARCHAR(255) NOT NULL,
    FullName VARCHAR(100) NOT NULL,
    StudentCode VARCHAR(20) NULL UNIQUE,
    RoleID INT NOT NULL,
    IsActive TINYINT(1) NOT NULL DEFAULT 1,
    CreatedAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_account_role FOREIGN KEY (RoleID) REFERENCES Role(RoleID)
        ON UPDATE CASCADE ON DELETE RESTRICT,
    INDEX idx_account_search (FullName, StudentCode, Email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 3. Bảng Club (Thông tin Câu lạc bộ)
CREATE TABLE IF NOT EXISTS Club (
    ClubID INT AUTO_INCREMENT PRIMARY KEY,
    ClubName VARCHAR(150) NOT NULL,
    Description TEXT NULL,
    ContactInfo VARCHAR(255) NULL,
    ManagerID INT NOT NULL,
    CONSTRAINT fk_club_manager FOREIGN KEY (ManagerID) REFERENCES Account(AccountID)
        ON UPDATE CASCADE ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 4. Bảng Club_Member (Thành viên Câu lạc bộ)
-- MemberRole chuẩn hóa: 'Member', 'Board Member', 'Event Supporter'
-- Status chuẩn hóa: 'Active', 'Inactive'
CREATE TABLE IF NOT EXISTS Club_Member (
    MemberID INT AUTO_INCREMENT PRIMARY KEY,
    AccountID INT NOT NULL,
    ClubID INT NOT NULL,
    MemberRole VARCHAR(50) NOT NULL DEFAULT 'Member',
    Status VARCHAR(30) NOT NULL DEFAULT 'Active',
    JoinedDate DATE NULL,
    CONSTRAINT uq_club_member UNIQUE (AccountID, ClubID),
    CONSTRAINT fk_member_account FOREIGN KEY (AccountID) REFERENCES Account(AccountID)
        ON UPDATE CASCADE ON DELETE CASCADE,
    CONSTRAINT fk_member_club FOREIGN KEY (ClubID) REFERENCES Club(ClubID)
        ON UPDATE CASCADE ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 5. Bảng Event (Sự kiện)
-- Status chuẩn hóa: 'Draft', 'Published', 'Cancelled'
CREATE TABLE IF NOT EXISTS Event (
    EventID INT AUTO_INCREMENT PRIMARY KEY,
    ClubID INT NOT NULL,
    EventName VARCHAR(200) NOT NULL,
    Description TEXT NULL,
    Location VARCHAR(255) NOT NULL,
    StartTime DATETIME NOT NULL,
    EndTime DATETIME NOT NULL,
    RegistrationDeadline DATETIME NOT NULL,
    MaxCapacity INT NULL,
    Status VARCHAR(30) NOT NULL DEFAULT 'Published',
    CreatedAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_event_club FOREIGN KEY (ClubID) REFERENCES Club(ClubID)
        ON UPDATE CASCADE ON DELETE CASCADE,
    INDEX idx_event_status_time (Status, StartTime)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 6. Bảng Event_Registration (Đăng ký sự kiện)
-- Status chuẩn hóa: 'Registered', 'Cancelled'
CREATE TABLE IF NOT EXISTS Event_Registration (
    RegID INT AUTO_INCREMENT PRIMARY KEY,
    EventID INT NOT NULL,
    AccountID INT NOT NULL,
    RegDate DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    Status VARCHAR(30) NOT NULL DEFAULT 'Registered',
    CONSTRAINT uq_event_account UNIQUE (EventID, AccountID),
    CONSTRAINT fk_reg_event FOREIGN KEY (EventID) REFERENCES Event(EventID)
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_reg_account FOREIGN KEY (AccountID) REFERENCES Account(AccountID)
        ON UPDATE CASCADE ON DELETE RESTRICT,
    INDEX idx_reg_event_status (EventID, Status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 7. Bảng Attendance (Điểm danh / Check-in)
-- AttendanceStatus chuẩn hóa: 1 (Present), 0 (Absent)
CREATE TABLE IF NOT EXISTS Attendance (
    AttendanceID INT AUTO_INCREMENT PRIMARY KEY,
    RegID INT NOT NULL UNIQUE,
    AttendanceStatus TINYINT(1) NOT NULL DEFAULT 1,
    CheckInAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CheckedInBy INT NOT NULL,
    CONSTRAINT fk_att_reg FOREIGN KEY (RegID) REFERENCES Event_Registration(RegID)
        ON UPDATE CASCADE ON DELETE CASCADE,
    CONSTRAINT fk_att_checker FOREIGN KEY (CheckedInBy) REFERENCES Account(AccountID)
        ON UPDATE CASCADE ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Đăng Ký & Hủy Đăng Ký Sự Kiện (Chống Vượt Chỗ & Chống Trùng)

Theo Mục 5.1 (Hồ sơ Tuần 3) và BPMN Tuần 2, luồng đăng ký bắt buộc sử dụng PDO Transaction và khóa dòng SELECT ... FOR UPDATE trên bảng Event.

  1. Xác thực: Kiểm tra phiên đăng nhập (lấy AccountID từ $_SESSION, tuyệt đối không lấy từ input của client) và kiểm tra CSRF Token.
  2. Mở Transaction: Gọi $pdo->beginTransaction().
  3. Khóa bản ghi sự kiện: Thực thi SELECT * FROM Event WHERE EventID = :eventId FOR UPDATE.
  4. Kiểm tra điều kiện:
    • Nếu sự kiện không tồn tại hoặc Status != 'Published' → Rollback & báo lỗi.
    • Nếu thời gian hiện tại NOW() > RegistrationDeadline → Rollback & báo "Sự kiện đã quá hạn đăng ký".
    • Kiểm tra bản ghi trong Event_Registration của (EventID, AccountID): Nếu đã có và Status = 'Registered' → Rollback & báo "Bạn đã đăng ký sự kiện này trước đó".
    • Nếu MaxCapacity IS NOT NULL: Đếm số lượt SELECT COUNT(*) FROM Event_Registration WHERE EventID = :eventId AND Status = 'Registered'. Nếu CurrentCount >= MaxCapacity → Rollback & báo "Sự kiện đã hết chỗ".
  5. Ghi dữ liệu: Nếu chưa có bản ghi thì INSERT INTO Event_Registration; nếu đã có bản ghi ở trạng thái 'Cancelled' thì UPDATE Status = 'Registered', RegDate = NOW().
  6. Hoàn tất: Gọi $pdo->commit() và hiển thị trạng thái Registered.
Quy tắc Hủy đăng ký (BPMN Tuần 2 & AC06): Người tham gia chỉ được hủy khi còn trong hạn đăng ký (NOW() <= RegistrationDeadline) và chưa điểm danh. Khi hủy, cập nhật Event_Registration.Status = 'Cancelled' để nhường chỗ trống.
Luồng Cốt Lõi 2 · UC12 / FR15 / PB18-PB19

Điểm Danh Sự Kiện (Check-in) & Xử Lý 3 Tình Huống

Theo Đặc tả UC12 và Tiêu chí nghiệm thu PB18, PB19, màn hình Điểm danh (SCR14) phải phản hồi kết quả tìm kiếm trong vòng ≤ 2–3 giây và xử lý chính xác 3 trường hợp:

Trường hợp 1: Người tham gia chưa đăng ký hợp lệ (PB19 - Mục 1)

Khi tra cứu theo Họ tên hoặc MSSV (StudentCode) mà không khớp bản ghi nào có Status = 'Registered' trong sự kiện: Hệ thống hiển thị đúng thông báo "Không tìm thấy thông tin đăng ký cho người tham gia này" và không tự động ghi nhận điểm danh.

Trường hợp 2: Người tham gia đã được điểm danh trước đó (PB19 - Mục 2)

Khi bản ghi RegID đã tồn tại trong bảng Attendance với AttendanceStatus = 1: Hệ thống thông báo "Người tham gia đã được điểm danh" (kèm thời điểm CheckInAt) và chặn tạo bản ghi điểm danh trùng (nhờ ràng buộc UNIQUE(RegID)).

Trường hợp 3: Đã đăng ký hợp lệ & Chưa điểm danh (PB19 - Mục 3)

Người có quyền (Club Manager hoặc Authorized Club Member) nhấn xác nhận có mặt → Hệ thống INSERT INTO Attendance (RegID, AttendanceStatus, CheckInAt, CheckedInBy) VALUES (:regId, 1, NOW(), :checkerAccountId) và cập nhật ngay bộ đếm số người có mặt trên giao diện.

Lưu ý phân biệt trùng tên (UC12 - 3b): Kết quả tra cứu luôn hiển thị đầy đủ FullName + StudentCode + Email để người điểm danh phân biệt chính xác khi có 2 sinh viên trùng họ tên.

Các Quy Tắc Nghiệp Vụ Bắt Buộc Khác (Business Rules Từ Backlog Tuần 2)

BR01 · Đăng ký tài khoản (PB01)

Mật khẩu phải từ 8 ký tự trở lên. Email và MSSV (StudentCode) không được trùng với tài khoản đã tồn tại. Tài khoản sinh viên tự đăng ký mặc định gán vai trò 'Event Participant'.

BR02 · Khóa tài khoản (PB04)

Khi System Admin khóa tài khoản (IsActive = 0), tài khoản đó không thể đăng nhập và nếu đang có phiên hoạt động thì bị từ chối ở request kế tiếp. Không cho phép Admin tự khóa chính mình.

BR03 · Bảo vệ Club Manager cuối cùng (PB10)

Khi cập nhật vai trò/trạng thái thành viên trong CLB, hệ thống chặn thao tác tự gỡ quyền hoặc vô hiệu hóa người giữ quyền quản lý CLB duy nhất còn lại.

BR04 · Ràng buộc Tạo/Sửa sự kiện (UC07 / PB11)

RegistrationDeadline <= StartTime < EndTime. Nếu có nhập MaxCapacity thì phải > 0. Khi sửa sự kiện, không được giảm MaxCapacity xuống thấp hơn số người đang ở trạng thái 'Registered'.

BR05 · Hủy sự kiện bảo toàn dữ liệu (UC07 / PB12)

Khi Club Manager hủy sự kiện, hệ thống chuyển Event.Status = 'Cancelled' (không xóa vật lý dòng dữ liệu) và giữ nguyên toàn bộ lịch sử Event_Registration liên quan.

BR06 · Công thức Thống kê cơ bản (PB20 / FR16)

Theo từng sự kiện:
• Số đăng ký: COUNT(RegID WHERE Status='Registered')
• Số tham dự: COUNT(AttendanceID WHERE AttendanceStatus=1)
• Vắng mặt: Số đăng ký - Số tham dự (Tỷ lệ = Tham dự / Đăng ký * 100%).

1. CÔNG NGHỆ & KIẾN TRÚC BẮT BUỘC (THREE-TIER MONOLITH):
- Frontend: HTML5, CSS3, Bootstrap 5, Vanilla JavaScript (Responsive cho PC & Mobile theo NFR07).
- Backend: PHP 8.x thuần (Monolith), sử dụng PDO với Prepared Statements 100%, quản lý phiên bằng PHP Session, mật khẩu dùng password_hash() và password_verify(), mọi form POST phải kiểm tra CSRF Token, mọi dữ liệu in ra HTML phải bọc htmlspecialchars().
- Database: MySQL (InnoDB Engine) gồm đúng 7 bảng chuẩn hóa 3NF:
  + Role (RoleID, RoleName) -> Giá trị: 'System Administrator', 'Club Manager', 'Club Member', 'Event Participant'
  + Account (AccountID, Email UNIQUE, PasswordHash, FullName, StudentCode UNIQUE, RoleID FK, IsActive TINYINT(1) DEFAULT 1, CreatedAt)
  + Club (ClubID, ClubName, Description, ContactInfo, ManagerID FK)
  + Club_Member (MemberID, AccountID FK, ClubID FK, MemberRole DEFAULT 'Member' ['Member', 'Board Member', 'Event Supporter'], Status DEFAULT 'Active' ['Active', 'Inactive'], JoinedDate)
  + Event (EventID, ClubID FK, EventName, Description, Location, StartTime, EndTime, RegistrationDeadline, MaxCapacity NULLABLE, Status DEFAULT 'Published' ['Draft', 'Published', 'Cancelled'], CreatedAt)
  + Event_Registration (RegID, EventID FK, AccountID FK, RegDate, Status DEFAULT 'Registered' ['Registered', 'Cancelled']) -> UNIQUE(EventID, AccountID)
  + Attendance (AttendanceID, RegID FK UNIQUE, AttendanceStatus TINYINT(1) DEFAULT 1, CheckInAt, CheckedInBy FK)

2. CƠ CHẾ PHÂN QUYỀN 2 TẦNG (RBAC):
- System Administrator: Chỉ truy cập SCR16 (Quản trị tài khoản & quyền hệ thống: tạo, khóa/mở khóa IsActive, đổi RoleID).

- Club Member được ủy quyền: Tài khoản có Role='Club Member' VÀ bản ghi Club_Member có Status='Active' VÀ MemberRole IN ('Board Member', 'Event Supporter') được quyền truy cập SCR13 (Danh sách đăng ký) và SCR14 (Điểm danh).
- Club Member thường (MemberRole='Member') và Event Participant: Chỉ được xem thông tin CLB/Sự kiện, đăng ký/hủy đăng ký sự kiện (SCR09) và xem hoạt động cá nhân (SCR12). Bị chặn 403 Forbidden nếu truy cập trực tiếp URL của SCR13, SCR14.

3. LOGIC NGHIỆP VỤ TRỌNG TÂM:
- Đăng ký sự kiện (UC09 / FR12 / PB15): Bắt buộc dùng PDO Transaction + `SELECT * FROM Event WHERE EventID = ? FOR UPDATE` để kiểm tra sự kiện đang 'Published', còn hạn (`NOW() <= RegistrationDeadline`), chưa đăng ký trùng và còn chỗ (`CurrentRegistered < MaxCapacity` nếu MaxCapacity khác NULL). Nếu hợp lệ thì INSERT hoặc UPDATE lại bản ghi 'Cancelled' thành 'Registered'.
- Điểm danh (UC12 / FR15 / PB18-PB19): Tra cứu theo FullName hoặc StudentCode trong <= 2 giây. Xử lý rõ 3 trường hợp:

  (2) Đã điểm danh rồi -> Báo "Người tham gia đã được điểm danh" và chặn ghi trùng.
